# setuptools is held at 80.9.0 — the last release that still ships `pkg_resources`.
# `resemble-perth` (Chatterbox's watermarker, see below) imports pkg_resources but
# declares no dependencies at all, and chatterbox-tts declares no setuptools bound.
# Under setuptools 82.0.1 the import fails, perth swallows it and sets its
# watermarker class to None, and ChatterboxTurboTTS construction dies with a
# misleading `TypeError: 'NoneType' object is not callable`. Proven in the v0.6.1
# Plan 4 Phase 8a isolated environment; 80.9.0 restores it.
# This is deliberate COMPATIBILITY DEBT, authorized by the maintainer for this
# release, NOT a preference for older setuptools: pkg_resources is deprecated and
# was slated for removal from 2025-11-30. Revisit and move forward as soon as the
# upstream dependency stops importing it.

# --- Local AI voice cloning (Chatterbox Turbo) — OPTIONAL engine ---
# v0.6.1 Plan 4 Phase 8. Engine package verified against the exact published wheel
# on 2026-08-15: chatterbox-tts 0.1.7 (2026-03-26, MIT, requires-python >=3.10).
# The Turbo model is loaded from `chatterbox.tts_turbo.ChatterboxTurboTTS` — the
# package root does NOT export that symbol, so `from chatterbox import
# ChatterboxTurboTTS` (which the upstream docs show) fails against this release.
# Model weights are ResembleAI/chatterbox-turbo, MIT, ~3.86 GiB, downloaded on
# demand into the existing in-tree HuggingFace cache; nothing is bundled.
#
# THIS BLOCK IS NOT ADDITIVE. chatterbox-tts pins its stack exactly, which pulls
# the shared scientific stack DOWN:
#     torch         2.13.0 -> 2.6.0      transformers  5.15.0 -> 5.2.0
#     numpy         2.5.2  -> 1.26.4     safetensors   0.8.0  -> 0.5.3
# (sympy follows torch to 1.13.1; ~57 further packages arrive transitively,
# including gradio's web stack, for about +1.15 GB of installed size.)
# scipy 1.17.1 above declares numpy>=1.26.4,<2.7, so 1.26.4 is the one version in
# the overlap — which is why it is pinned rather than left to the resolver.
# Phase 8a proved on that combined stack, in an isolated Python 3.12.10 venv, that
# Kokoro still works: a real CPU synthesis through tts/kokoro_synth.py produced
# byte-identical audio, and the full repository suite passed unchanged.
#
# No CUDA-specific PyTorch build is pinned here. Device selection (cuda -> mps ->
# cpu) happens at runtime; this file stays cross-platform and CPU-only.
# Gated to <3.13 alongside Kokoro: the venv is capped there by Kokoro's wheels and
# nothing above it was proven. The pins below are the ones chatterbox-tts leaves
# floating (a range, or no bound at all) plus the four headline downgrades, stated
# explicitly so the effect is visible here instead of buried in a resolution.
