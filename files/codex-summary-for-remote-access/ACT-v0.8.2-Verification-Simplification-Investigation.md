## What a run must guarantee

Design for trusted repository tests and cooperating developers. Ordinary Python can launch other programs. The contract covers accidental heavyweight work at known ACT boundaries, protection of owner data, and an honest result for the requested scope. Deliberate shell circumvention is outside scope.

1. **Routine.** Use the checkout's root `.venv`, the existing resolver and standard pytest. Classify paths before importing tests, including collection-only. Keep sparse `ACT_EFFECTS` declarations and guarded membership. Split a mixed module if importing it has side effects. Scrub plugin autoload, ambient opt-ins and startup/cache overrides before starting the interpreter. Keep checks at real backend and desktop entrypoints before side effects, including direct calls into acceptance, qualification and scaling. Use disposable TEMP, caches and output roots, ordinary stand-ins and existing protected-state checks. New or ambiguous sensitive work stays pending review. Never infer permission from an environment variable, an empty selection or a fixture's location.
2. **Guarded.** Route `v3-planning` and `v3-supervisor` through their own runner and disposable roots. Keep their lifetime checks through teardown. Run an actual fixture installation only with authorization covering it. A guard failure fails its stage. Keep production child ownership code intact.
3. **Heavyweight.** Require explicit owner approval per attempt, naming scope, candidate, platform, effects and budget. Start only through supervised, named operations. Serialize heavyweight work across checkouts. Keep native desktop leases. A timeout, uncertain ownership or interrupted cleanup blocks another heavy run until the owner confirms cleanup. Never kill processes by image name. On macOS, a nested new session can escape an outer process group. Require native proof of ownership and cleanup for that path before enabling it.

Use `winproc.run_supervised` for collection and execution with a stage deadline, Windows kill-on-close Job or POSIX process group. Move its `on_start` callback inside cleanup protection. Only remove fresh run-owned scratch after no-follow checks. Use the existing session probe and JUnit to reconcile requested, collected, deselected, executed and skipped nodes. Require a real stage exit, required guards, expected session identity and clean termination before PASS. Missing work, unexpected skips, timeout and interruption are visible non-passing outcomes.

Keep `--plan` side-effect free. **Quick** runs named static checks and a bounded import smoke. **Focused** runs named tests or feature tests and their guards. **Changed** uses Git, feature routes and reverse imports, reporting gaps without widening. **Regression** runs named component selections. **Qualification** takes a named scenario or explicit journeys. **Full** takes the release partition on one native platform. Routine modes list native obligations without starting them.

For each run record platform, interpreter, command, scope, candidate, results and cleanup. Reuse privacy-filtered hashing. Record HEAD and a fingerprint of the actual dirty public inputs, including relevant untracked inputs. Compare start and finish. If inputs cannot be identified, withhold an exact candidate claim. Keep local JUnit, session and stage records. Historical FAIL, interrupted and legacy results stay readable under their original rules. Routine evidence never qualifies a different commit automatically.

## Shortest safe migration

1. **One routine cutover.** After approval, update the active contract, GATE and current Handoff. Correct D-5 and fixture destinations first. Wire scope selection, sanitized startup, disposal and the existing stage judge before deleting both sides of child accounting in the same change. Drop only tests of retired machinery. Keep focused usable throughout and wire quick, changed, focused feature and named regression to the same dispatcher. Keep heavy execution gated during cutover.
2. **Fold routine 1A-3 and the small part of 1B needed for truthful reporting into that cutover.** Retain historical readers and feature obligations. Defer wholesale inventory migration, fine-grained invalidation and automatic release credit. Reduce 1A-2 to admission for the first genuinely needed heavy run. Prefer an owner-supervised single attempt and an OS lock with manual recovery on uncertainty. Defer SQLite issuance, delegated grants and automatic crash recovery. Keep full and journey execution unavailable wherever serialization or ownership is unproved.
3. **Resume application work.** Proceed to Phase 2's classified, dry-run repository hygiene, leaving protected and undecided material alone. Then run authorized Phase 3A Windows uv feasibility and 3B native macOS proof. Proceed to Phase 4 locked base provisioning after both or an explicit macOS deferral, then isolate Qwen3, OmniVoice, Kokoro and Chatterbox in roadmap order. Keep the root `.venv`, existing regression contracts and VERSION 0.8.1. Gate redesign adds no prerequisite to these product decisions beyond the checks their work uses.
