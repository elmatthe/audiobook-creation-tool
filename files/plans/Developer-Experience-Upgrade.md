## Goal

Deliver a reproducible, entirely folder-contained uv-based ACT with independently provisioned heavyweight TTS engines, a substantially cheaper and more reliable agent verification workflow, concise user and developer documentation, and safe automatic development-artifact lifecycle management, while preserving the existing double-click setup/use experience and all currently supported application behaviour. Complete native Windows and Apple Silicon macOS qualification and independent review before recommending the candidate for explicit owner merge approval.

## Scope

### In

1. **Developer workflow:** adopt the canonical AI Workspace conventions; reconcile the old documentation contract; compact Briefing and Handoff; provide explicit agent instructions, stable feature maps and one source of truth per fact.
2. **Verification:** keep the existing gate entrypoint, simplify its implementation and metadata, introduce six proportional modes, automatic selection/evidence, explicit heavyweight authorization and resumable release qualification. Preserve meaningful tests, containment and honest results.
3. **Packaging:** pinned local uv and managed CPython 3.12, separate locked projects for base and four local engines, repository-local shared cache, native platform profiles, optional developer groups, offline-first health/repair, recoverable legacy migration, relocation and path-length handling.
4. **Engine modularity:** explicit engine registry, shared subprocess lifecycle and model-management primitives, existing optional selection/first-use setup and engine-specific synthesis contracts.
5. **User documentation and release builder:** concise README with real OS security guidance and screenshots; extend the existing committed-source packaging builder and make it deterministic; support both GitHub source ZIP and official release ZIP; preserve all historical Windows/macOS archives in root `dist/`.
6. **Repository hygiene:** classify existing development files, remove proven obsolete artifacts, keep valuable evidence and runtime data, enforce safe bounded cleanup and retention during agent work.
7. **Qualification:** measured before/after performance, native platform tests, final Codex independent bug hunt, scoped remediation, evidence reconciliation and an explicit readiness verdict.

- uv workspaces, a single shared dependency resolution across incompatible engines, dynamic third-party plugin discovery, persistent HTTP engine servers, global caches, global PATH changes, system Python modification, administrator elevation for normal setup, alternative packaging frameworks without a separately approved architectural change.
- Deleting user files, runtime data, published archives, protected `files/Archives/`, unique required evidence, active agent work or unknown local artifacts; rewriting Git history; merging, tagging, publishing or deploying without explicit approval.

### uv facts checked against current upstream documentation

- `uv python install` **registers interpreters in the Windows registry (PEP 514) by default** — a global write. Disable with `--no-registry` / `UV_PYTHON_INSTALL_REGISTRY=0` (and evaluate `UV_PYTHON_NO_REGISTRY` for discovery). It also places executables in a bin directory unless `--no-bin` / `UV_PYTHON_INSTALL_BIN=0`.
- Default `link-mode` is `hardlink` on Windows and `clone` (copy-on-write) on macOS; `symlink` is discouraged; `copy` is available (`UV_LINK_MODE`).
- PyTorch: per-project explicit indexes (`[[tool.uv.index]] explicit = true`) selected through `[tool.uv.sources]` with `marker` (platform) or `extra` (accelerator profile, with `[tool.uv] conflicts`). macOS has no CUDA builds.
- Python discovery also reads PATH and (Windows) the registry/Microsoft Store unless restricted (`python-preference = only-managed`, `UV_PYTHON_DOWNLOADS`, explicit `--python`). Exact flags must be re-checked against the pinned uv version's CLI help in Phase 3.

## Transitional-state rules (apply to Phases 3-6)

The repository must stay launchable and verifiable at every pushed checkpoint.

1. **One production route per environment at a time.** Each environment (base, then each engine) switches from pip to uv in exactly one checkpoint; until then its legacy installer stays the production route and keeps working. The only permitted dual state is "already-migrated environments use uv, not-yet-migrated ones use their legacy installer", tracked in a table in Handoff.
2. **Legacy interpreter stays until nothing references it — for existing and fresh installs.** Existing engine envs' `pyvenv.cfg` `home` points to `files/runtime-data/python`, and the not-yet-migrated engine installers resolve the base interpreter through hard-coded consumers (`APP_PYTHON_PARTS`, `app_base_python()`, `omnivoice_runtime`, `venv_integrity`, `cleanup_state`). Phase 6 retires the legacy interpreter only after every environment has been rebuilt on the uv-managed interpreter (or Phase 3 decision A2 keeps it as the managed interpreter).
3. **Profiles are explicit.** Every v0.8.1 install contains pytest (it is in both base locks), so its presence cannot identify a developer checkout. Migration assigns the profile from an explicit rule recorded in the receipt (default `user`; `dev` only through an explicit developer command or marker, never inferred from installed packages), and normal launches preserve the recorded profile.
4. **Base keeps Kokoro and Chatterbox until 5C/5D.** Phase 4's base project is a parity translation of today's base lock (including Kokoro/Chatterbox/torch 2.6.0 stacks, excluding pytest which moves to the dev group); 5C and 5D remove them from base in the same checkpoint that installs the isolated replacement and switches the runtime route.

6. **Owner production install is never the test subject.** Migration experiments use disposable copies; the owner's primary checkout (branch `0.8.1`, daily use) is untouched until the owner chooses to switch. Keep baseline/current production safe.
7. **Seams have deletion criteria.** Every temporary compatibility seam is listed in Handoff with the checkpoint that removes it; Phase 6 fails its exit criteria if any seam remains.
8. **Every pushed checkpoint can still produce a usable distribution (Revision 3).** `scripts/shared/release.py` packages an explicit root allowlist (README, `config.toml`, LICENSE, the launchers, the clone WAVs, tracked `scripts/`), which today has no `pyproject.toml` or `uv.lock`.
