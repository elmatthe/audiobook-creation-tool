## 4. Selected implementation architecture

**Choose a sibling isolated environment at `.venv-omnivoice/` for this narrow release.** It is a standalone venv made with ACT's proven portable Python 3.12. It avoids ACT main `.venv` and Qwen3's separate `.venv/engines/qwen3`, both of which use incompatible Transformers distributions. A sibling also avoids expanding the main venv replacement/repair transaction to protect an additional nested child. This is a deliberately simpler initial choice; change it only if a focused reproducible proof shows the sibling cannot satisfy existing setup or packaging rules.

Use a small `scripts/tts/omnivoice_runtime.py` (availability, paths, six-hash + bundled transcript validation), `omnivoice_worker.py` (heavy imports and model generation inside the dedicated interpreter) and `omnivoice_synth.py` (small parent adapter to existing chunk assembly/output publication). Implement only the new, needed code; reuse `qwen3_process` or current shared process supervision for owned subprocess termination, worker timeouts and cancellation. Place models, safe cache, installation receipts, logs and worker scratch under `files/runtime-data/omnivoice/` or existing permitted in-repo temporary work roots. Explicitly exclude the venv, model files, caches, scratch and private outputs from Git and release ZIPs. **Do not install any OmniVoice package in `scripts/requirements.txt` or alter Qwen3's locked packages.**

At implementation time, pin a tested OmniVoice PyPI release (initial candidate `omnivoice==0.2.1`), compatible PyTorch/CUDA wheel build and transitive dependencies for Windows x64/CPython 3.12; record a reproducible package manifest appropriate to the existing installer. Pin the exact Hugging Face model revision, required audio tokenizer location, sizes and SHA-256s. **Important upstream detail:** `OmniVoice.from_pretrained()` can fetch a separate `eustlb/higgs-audio-v2-tokenizer` snapshot when `audio_tokenizer/` is missing. The ACT installer must either provide a complete, pinned local `audio_tokenizer/` or stage and verify that separate tokenizer under the same explicit consent, using local paths and an offline/no-network synthesis smoke test. Download into an app-controlled cache/staging area after explicit consent; verify before considering it installed. No ambient Hugging Face cache fallback or implicit library download during synthesis. A model/tokenizer not provably complete is NOT READY; an unknown/broken environment is not automatically deleted. Never modify owner's existing engine environments to make dependency resolution work. Record actual download bytes, disk use and GPU support rather than claiming a particular VRAM minimum is guaranteed.

**Superseded by the Phase 2 correction (owner decision 2026-11-13, Phase 2 correction) -- OmniVoice now conditions directly on the owner-curated recordings, see section 3; kept as history:** **Mandatory OmniVoice-only maximum-10-second, silence-safe conditioning (owner decision 2026-11-13):** For each of the six approved source WAVs, verify its original SHA-256, then deterministically extract its own decoded frames from **0.000 seconds to a sample-frame-accurate end no later than 10.000 seconds**, using its decoded sample rate. The end is as close to 10.000 seconds as is safe, never later: the final audible word is complete and the last sample lies inside a natural quiet interval after it (an adaptive, noise-floor-aware energy check over multiple frames, never one low sample or a zero crossing), keeping a short naturally quiet tail where the recording permits. Never end during a vowel, consonant, sibilant, breathy ending or unfinished word; never append artificial silence or fade to disguise an incomplete word; never extend past 10 seconds to finish a word; if the nearest safe natural pause is earlier, use that shorter duration; if no defensible end exists, report the ambiguity rather than guess. Acoustic silence alone does not prove a word is complete: verify the spoken end-word against the transcript. Pass **only this derived excerpt**, never the full roughly 15-second original, into `create_voice_clone_prompt(ref_audio=..., ref_text=...)`. Generate the excerpt in ignored, app-owned runtime scratch/cache without altering or duplicating the shipped six originals. Preserve Chatterbox/Qwen3's full-length reference behavior. Record each excerpt's crop, end frame, duration, PCM/WAV hashes, last spoken word, trailing-quiet evidence and excerpt transcript in a small OmniVoice-only identity authority; the six crops and transcripts stay provisional until the owner approves them in Session 4.

**Reference-text alignment is essential:** (owner decision 2026-11-13, Phase 2 correction) each OmniVoice recording is paired with the owner's own written transcript of exactly that recording; the six transcript SHA-256s are pinned beside the six WAV SHA-256s, any mismatch fails closed, no ASR is used, and no prefix relation to the Qwen3 transcripts is required. The reusable clone prompt is keyed by the WAV SHA-256, frames and rate, transcript SHA-256, model revision, engine version, prompt format, preprocessing flag and dtype (identity schema 2), so a changed recording or transcript never reuses a prompt. *Superseded Phase 2 text:* The full-length bundled transcript may not be supplied as `ref_text` for an excerpt of at most 10 seconds. Derive a separate, accurate six-entry **OmniVoice excerpt transcript** set, by checking the actual speech within each excerpt against the existing approved full transcript; do not automatically truncate by character count or guess missing words. Keep the existing canonical transcripts untouched. Track excerpt transcript text/identity alongside the original WAV hash, crop parameters and excerpt checksum; any uncertain end-word must be flagged for the owner's Session 4 review. Use these excerpt-matched texts for the proof and generation in Sessions 1–2; treat them as provisional until the owner approves them in Session 4. **Do not use Whisper ASR** or install optional `omnivoice[tn]` for the six approved voices. Safe prompt caching may use upstream `VoiceClonePrompt.save/load` under app-owned paths, keyed by **original WAV SHA, cropped-audio checksum/crop settings, excerpt transcript SHA, model revision and preprocessing version**, so a changed source, crop, transcript or model cannot reuse an incompatible prompt. Reuse the prompt across chunks; only load trusted app-created prompt files, never untrusted pickle-like `.pt` inputs.

**Shared text-normalization contract — integrate rather than duplicate:** Add the stable `"omnivoice"` engine to the existing `speech/glossary.py` engine-scope allowlist, `speech/profiles.py` route/profile, and `speech/data/modes.json` per-class row. Use the current `SpeechPrepSnapshot` frozen at Create, call the existing `speech.pipeline.prepare(read_source_text(src), speech_prep, OMNIVOICE_ROUTE)` **once per file in the main ACT process, before any splitting or worker IPC**, and send only its prepared text/chunks to the isolated model worker. Preserve `utf-8-sig` decoding, `Title:`/`Author:` omission, heading handling, chunk/source order and diagnostic `PreparedText.details()` reporting. For structural grouping initially follow the existing Qwen3 heading-as-paragraph local route if appropriate, but use an OmniVoice-specific, empirically safe chunk ceiling rather than assuming Qwen3's 600 characters are safe. No user-facing normalization controls, duplicated rules, unreviewed punctuation substitutions, or global changes to other backend routing. Keep `phoneme_markup=False` unless OmniVoice documents and passes proof for compatible markup; Kokoro's `[word](/phonemes/)` markup must not be sent to OmniVoice.

**Current ACT rules and deliberate non-rules (verified on v0.7.2 branch):** The single-pass, integrity-checked `speech/normalize.py` uses **16 classes**: `HYG` (invisible characters, spacing, ligatures); `CARD` (cardinals); `DEC` (decimals); `ORD` (ordinals); `PCT` (percentages); `CUR` (currency); `YEAR` (cued years/decades); `TIME` (clock notation and AM/PM); `RATIO` (cued ratios); `DATE` (unambiguous month/ISO dates); `RANGE` (cued ranges); `FRAC` (fractions); `UNIT` (measurements/temperatures); `TITLE` (cued honorifics); `ROMAN` (cued Roman numerals); and `SYM` (supported symbols such as ampersands and multiplication). The original `numbers_en.py` fixes U.S.-English verbalization. Literal URLs, email, file paths, metadata, non-English passages, and ambiguous/identifier-like strings are protected or left as written; this **does not** mean that the model is guaranteed to pronounce the preserved literal text well. Notably `7:15` with a time cue differs from an uncued `3:16`; `3:1` with a ratio cue differs from a clock time; `March 5, 2024` is supported while slash dates such as `03/04/2024` remain ambiguous; `1999` without a cue can remain unexpanded; and `007`, `24/7`, `R2-D2`, `Version 1.2.3`, negative numbers, addresses, and prose `e.g.`/`i.e.` deliberately avoid blind rewriting. Existing `glossary.user.json` and `modes.user.json` provide owner-controlled, engine-scoped adjustment without changing source books; **`native` suppresses both class rewriting and overlapping glossary rewrites**, whereas `glossary_only` permits owner glossary changes. Handle protected/ambiguous limitations by owner-approved, narrowly scoped corrections, not blanket conversion.

**OmniVoice per-engine default and evidence rule:** Add a complete OmniVoice mode-table row, provisionally **`expand` for all 16 classes** (including mechanical `HYG`) to match the existing Qwen3/Chatterbox baseline; this is a starting hypothesis, **not a claim that OmniVoice's native readings are inferior**. Keep the historical mode rows and the 60 existing owner G1 verdicts untouched. During Phase 4, compare actual audible OmniVoice `v1` behavior with native/off **only for classes that sound wrong**; the owner approves any switch of an OmniVoice class to `native` or `glossary_only` and any specific OmniVoice glossary entry. Preserve the rest of the class matrix, text integrity checks, user overrides and run-snapshot determinism. A mere new engine row does not authorize edits to `classes.py`, `numbers_en.py`, existing `units.json`/`lexicon.json`, or a retroactive change to the 60 historical comparison records. If a rule/data edit is genuinely required, obtain owner approval first and follow the existing `RULESET_VERSION`/fingerprint/test protocol.

**Focused normalization proof before owner listening:** Add fixture-driven tests that run `prepare()` with both `v1` (production default) and `off`, check exact prepared text/edits/unchanged spans for all 16 classes using the **existing golden corpus**, verify that the frozen GUI run passes the snapshot through OmniVoice's parent adapter into chunking/worker without double-normalization, and verify source-span integrity and diagnostics. - **Sessions 1–4:** run only the smallest practical targeted unit tests, relevant fixture-driven setup/worker/GUI tests, lightweight static/import checks, and the explicitly listed local hands-on smoke tests for the current phase.
