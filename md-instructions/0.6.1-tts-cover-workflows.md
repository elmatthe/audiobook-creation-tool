## 1. What this plan is

Plan 4 is the **first production adoption of Plans 2 and 3**. It replaces the ad-hoc
importing, cancellation and logging in the TTS and Cover Image panels with the shared
foundation, and adds the Cover browser views, Cover folder importing and the pinned,
probed HEIC/HEIF capability that Decision 54A requires.

It also **retires EPUB from the product**. TTS becomes a PDF/TXT-only tool with one unified
queue, and the EPUB-specific source is preserved in a tracked, non-runtime reference archive
(§1.2, §4.4).

It also integrates **Chatterbox** as a third TTS engine alongside Edge and Kokoro, cloning
**four maintainer-supplied reference recordings** into four production voices, with a
maintainer listening-evaluation gate before any voice is locked into the registry.

It is **not** a theme conversion. Both panels stay classic on Windows; converting the
remaining five panels to the `ACT.*` design system belongs to Plan 9.

## 4. Contracts that must survive unchanged

These are closed. No Plan 4 design may weaken any of them.

### 4.1 TTS

- **PDF and TXT are the only TTS input types** (§1.2). This holds for direct file selection,
  folder traversal, dialog filters, dispatch and retry alike.
- **EPUB cannot enter a frozen run by any route** — not through the UI, the importer, the
  file manager, a retry, stale persisted state, or a direct internal dispatch call.
- **52B's folder-batching clause still binds**: folder traversal yields PDF/TXT occurrences
  only.
- **Mirrored output behaviour is preserved exactly.** A source at `input/Book 1/Ch 1.pdf`
  lands at `<run>/Book 1/Ch 1.mp3`; files directly in the root stay flat. Both the Edge
  path (`batch_convert.run_batch_convert`) and the Kokoro path (today inline in the TTS
  panel module, pre-Phase-5 path `epub2tts_gui.py`) must keep producing identical layouts.
- **Batch child-process isolation and timing defaults must not regress.** Per-source
  temp-chunk directories keyed on the mirrored relative path, `PDF_MAX_RETRIES`,
  `CHUNK_MAX_RETRIES`, `INTER_CHUNK_DELAY_SEC` and the voice timing presets stay as they are.
- The run directory is reserved **only after input validation**, never at panel build.
- **Adding Chatterbox must not change Edge or Kokoro behaviour in any way.** The twelve
  existing `VoiceEntry` rows, their `voice_id`s, their `display_label`s and every value in
  their `timing_preset` dicts stay byte-identical. `DEFAULT_VOICE_LABEL` remains Steffan.
- **A missing Chatterbox install must never break startup or the other two engines.** The
  import is lazy and probed, exactly as Kokoro's is.
- **A missing reference recording, derivative or cached conditional must also never break
  startup.** On a machine without the local assets, the app and every Edge/Kokoro voice
  still start and convert; the affected Chatterbox voices are either hidden or shown
  disabled with a truthful "setup required" status. **No broken selection may be offered,
  no substitute voice may be silently used, and nothing may be sourced from the internet
  to fill the gap.** See §4.3.

### 4.2 Cover Image — the destructive contract

Closed, and reported here exactly as it stands:

- **Standard output is the default.** `<base>/Cover-Image-Outputs/Cover-Image-N/`.
- **Source-side mode is opt-in**, off on every fresh build, never persisted.
- **`Create numbered copies` is preselected**, and turning the source-side toggle off
  resets the action back to it.
- **Replacement is never the default** and requires the complete existing chain:
  1. `Save beside source images` enabled;
  2. `Replace original files` selected;
  3. every source validated *before* the dialog (`validate_source_for_replacement`, plus
     the `REPLACEABLE_SUFFIXES` check that refuses formats written as `.jpg`);
  4. the per-run confirmation accepted — Cancel focused and default, Escape and window
     close both cancel, no suppression or memory of any kind.
- Replacement writes a complete temporary sibling, validates the finished image, then
  installs with a single `os.replace`. Never delete-then-rename.
- **Retry Failed must not overwrite a successful earlier output, and must not weaken the
  source-replacement confirmation.** A retry that includes replacement re-asks.

### 4.3 Chatterbox local reference assets — the raw/derived safety contract

`files/Chatterbox-Voice-Uploads/` holds **local, maintainer-supplied input recordings**.
Their only authorized provenance statement is:

> Maintainer-supplied local reference recording, authorized by the maintainer for use by
> this local Chatterbox integration.

**Claim nothing further.** Do not assert copyright ownership, speaker consent,
redistribution permission, or any public licence the maintainer did not state. Do not
attempt to identify the speakers.

**The four raw MP3s are read-only inputs.** They must never be staged, committed, pushed,
packaged, released, copied into `files/tests/`, overwritten, renamed, trimmed, normalized,
re-encoded in place, or modified in any way. Read them; never write to that directory.

**Derivatives.** If the selected model needs a shorter or format-converted reference clip,
generate it as a **new derivative file** in an already-ignored location — under
`files/runtime-data/` (ignored at `.gitignore:29`), e.g.
`files/runtime-data/chatterbox/reference-clips/`. Never write the derivative back over the
source.

**Cached voice identity data.** Any embedding, conditional or speaker cache likewise lives
only under `files/runtime-data/` — e.g. `files/runtime-data/chatterbox/conditionals/`.
Cached voice identity data is derived from the recordings and carries the same handling
rules as the recordings themselves.

**Deterministic mapping.** Every derivative and every cached conditional must be traceable
to its source by **SHA-256** — carry the source hash in the filename (e.g.
`female-1__a047d77fe191c1a9.wav`) and write a small manifest recording
`label → source path → full source SHA-256 → derivative path → parameters`. A stale
derivative whose recorded source hash no longer matches must be regenerated, never used.

**Preserve the source unconditionally.** If a derivative is invalid, truncated, or
generation fails, the raw recording is left exactly as it was. Failure never edits an input.

**Portability boundary — do not solve this silently.** These assets exist only on the
machine the maintainer put them on. Chatterbox voices will therefore not work on another
machine until the maintainer places the recordings there. **Do not bundle, commit, embed,
compress, or package the recordings or any cached voice identity data to make cross-machine
availability work.** That is a distribution decision about a real person's voice and it
belongs to the maintainer. Record it in `Handoff.md` as an open local-asset portability
boundary requiring explicit future authorization, and stop there.

**Archive root:** `files/archived-code/epub-tts/`

**Verified 2026-08-11:** `files/archived-code/` is **not currently ignored**

### 4.5 The unified PDF/TXT queue (decision 2A)

One queue. Directly added PDF/TXT files and folder-imported PDF/TXT occurrences **coexist in
the same queue and the same run**. There is no single-file mode and no batch mode.

`planning_groups()` will therefore yield **both** `direct` and `grouped`, requiring
`plan_multi_root` (Decision 41A). That is expected, not an error path.

All of the following are preserved simultaneously:

- **occurrence identity** and **deliberate duplicates** — the same path added twice stays
  two occurrences and is never silently deduplicated;
- **source provenance** — each occurrence knows whether it came from a direct add or a
  folder root, and which root;
- **natural ordering**;
- **mirrored placement for folder-derived inputs** (Decision 7A) — unchanged from today;
- **flat placement for directly added files** (Decision 31A);
- **frozen run snapshots** — the queue at capture is what runs;
- **exact retry configuration** — a retry re-runs against the original snapshot, and every
  item lands where it would originally have landed.

### 4.6 HEIC/HEIF output (decision 3A)

**Preserve the input image format.** A HEIC/HEIF input produces a HEIC/HEIF output.

**Never silently convert HEIC/HEIF output to JPEG.** If HEIC/HEIF *encoding* is unavailable,
the item fails with a truthful unsupported-capability result — it does not quietly become a
`.jpg`. A silent format substitution is a data-fidelity bug, and under source-side
replacement it would be destructive.

**Decode and encode capability are reported separately.** They are not the same capability
and must not be collapsed into one boolean: a build can read HEIC and be unable to write it.
The probe (Phase 1) exposes both, and the UI reports whichever is missing, accurately.

Real HEIC/HEIF behaviour is verified on **Windows** (Phase 12) **and on real Apple Silicon**
(Phase 13). Neither substitutes for the other.

### 4.7 Dependency-removal boundary — evidence before deletion

`ebooklib`, `beautifulsoup4` and `lxml` are currently *described* as EPUB parsing
dependencies. **That description is not evidence.** Do not pre-decide that all three can go.

For **each** package, before removing it:

1. **Enumerate every consumer** — production and test — by search, not by memory.
2. **Classify each consumer** as EPUB-only or shared.
3. **Remove the dependency only if no active non-archive consumer remains.** An archived
   file is not a consumer; a shared production file is.
4. **Update `bootstrap.py`'s `REQUIRED_IMPORTS` and any verification expectation
   consistently** — a removed package still listed there breaks a clean install.
5. **Run the dependency and clean-install contract tests.**
6. **Preserve exact pins for every dependency that is still required.** Removal is the only
   permitted change; no incidental version drift.

- **Does Chatterbox belong in Plan 4** — **yes**, explicitly. It remains a recorded scope

### 7.1 The one thing still genuinely open — and it is not a planning question

**Whether CPU Chatterbox inference is fast enough to be usable** is unknown until Phase 8
measures it. Decision 7A already dictates what happens either way: usable → proceed;
impractical → stop and return measurements. **No planning input is needed now**, and this
must not be treated as an unresolved requirement.
