## 11. Terminology

- **Book job** (or **book**) — one unit of work: a stable identity, a configuration, and its own
  imported-file list. The unit the user adds, duplicates, removes and navigates between. **The retry
  granularity.**
- **Workspace** — the ordered collection of book jobs plus the current selection.
- **Configuration** — everything about a book that is *not* an imported input (section 13.2).
- **Raw per-book value** — what the user typed on that book's own page.
- **Raw shared value** — what the user typed on the Shared Metadata page.
- **Effective value** — the value a run will actually use, resolved by section 15's precedence rule.
- **Empty book** — a book whose imported-file list is empty. **Invalid book** — a book a consumer's
  own validation rejects. Both are skipped safely and consume no number.

## 13. Book job and workspace contracts (Phases 1–2)

### 13.1 The book job

An immutable, `frozen=True, slots=True` record carrying:

- **a stable `book_id`** — minted once from an `importing.IdFactory`, opaque, never an index and
  never a path. It survives add, remove, reorder, navigation, a run, and a retry. **Index identity is
  forbidden**: the three existing panels remove by listbox index, and that is precisely the defect
  this model replaces;
- **a frozen configuration mapping**, deep-frozen through `job_control.freeze_options`, so a widget,
  variable, callable, thread or open file can never be stored in a book;
- **its own `importing.ImportedFileSnapshot`** — the book's imported inputs, defaulting to the empty
  snapshot at `INITIAL_REVISION`.

Derived, never stored: whether the book is empty, its file count, and its display label.

**A book job never holds a Tk variable, a widget, a `Path` to an output, a reserved run directory, a
planner, or a failure.** Outputs stay Plan 2's; failures stay Plan 3's.

### 13.2 Configuration versus imported inputs — the central split (49A)

The drop must state this once, in code, so no consumer can drift:

- **Configuration** is the frozen mapping. Everything a user chooses *about* a book — its metadata
  fields, its per-book options, and any per-book output-naming field Plan 7 later consumes.
- **Imported inputs** are the `ImportedFileSnapshot`, and nothing else.

**Duplicate Book copies the configuration mapping by value and starts the new book at the empty
snapshot.** A test must prove that a duplicated book shares no mutable state with its source, that
every configuration key survives, and that its file list is empty. A second test must prove the
split is enumerated in exactly one place, so a consumer cannot invent a third category.

### 13.3 Meaningful work (50A)

One central predicate answers "would removing this book lose work?". It is true when the book has any
imported file **or** any configuration value the user has actually set (as distinct from a default
the model supplied). It is false for a pristine, empty book.

Remove Book consults **only** this predicate to decide whether a consumer should confirm. Plan 6 does
not show the dialog — it supplies the answer, and the consumer's own `ask_confirm` shows it. A test
must prove a freshly added book is not meaningful, that adding a single file makes it meaningful, and
that setting a single configuration value makes it meaningful.

### 13.4 The workspace controller (Phase 2)

The workspace owns an ordered tuple of book jobs, the current selection, and a `Revision` that moves
only on a real change. Operations:

- **Add Book** — appends a new pristine book and selects it.
- **Duplicate Book** — inserts a copy of the current book per section 13.2 and selects it.
- **Remove Book** — removes the current book. **The workspace is never empty**: removing the last
  book leaves one pristine book, because Decision 13A begins with one book job and a zero-book
  workspace has no coherent `Book X of Y`.
- **Previous / Next** — move the selection by one. **Navigation does not wrap**, matching the
  existing `ImportedFileList` block-move idiom; at an end the action is simply unavailable.
- **Select** — by `book_id`, never by index.
- **Replace** — swap one book's configuration or file snapshot for a new frozen value.

**Invariants proved by test:** `1 <= X <= Y` always; `Y >= 1` always; every operation returns a
result carrying the operation, whether anything changed, the new frozen workspace snapshot and the
new selection; a no-op does not advance the revision; every update is **atomic** — a rejected
operation changes nothing at all; and the selected book's identity is preserved across every
operation that does not remove it.

**Navigation must preserve each book's independent state.** Moving away from a book and back returns
exactly the same configuration and file list. That is structural here — the state lives in the
model, not in widgets — and a test asserts it.

## 14. Folder to book construction (Decision 12A, Phase 3)

Phase 3 adds one pure function that turns an `ImportedFileSnapshot` into the ordered book jobs it
implies.

**Grouping key: the directory that directly contains the file** — that is, each file's immediate
parent. This is **not** `planning_groups`, which groups by the *selected root*; importing a folder of
twelve book directories must yield twelve books, not one.

Rules:

- Groups appear in the order their first file appears in the imported list, so the user's own root
  order is preserved and one root's books never migrate into another's.
- Files within a group keep the imported list's relative order. For folder scans that is already
  natural order, because `scan_roots` emits each directory's compatible files natural-sorted before
  descending. **For individually added files it is not**, because `validate_direct_files` deliberately
  never sorts — so the function must apply `importing.natural_key` within each group and a test must
  prove `1, 2, 10` for both entry paths.
- Individually selected files (`RootKind.DIRECT_FILES`, whose `mirroring_root` is `None`) are grouped
  by their own parent directory too. Decision 31A governs where their *outputs* go, which is Plan 2's
  business and is not decided here.
- Distinct directories are **never** merged, even when their names match.
- A directory yielding no compatible files yields no book.
- The function creates no directory, touches no filesystem, and reads nothing but the snapshot.

**How a folder import becomes books** is stated as a contract, not implemented against a panel: a
consumer commits an import through the existing `ImportCoordinator` exactly as it does today, then
hands the committed snapshot to this function and replaces its workspace atomically. Plan 6 provides
the function and the replacement operation; Plan 7 wires them to a button.

## 15. Shared Metadata precedence (Decision 20B, Phase 4)

### 15.1 The three values, kept apart

The model separates, and never conflates:

1. the **raw per-book value**, stored in the book's configuration;
2. the **raw shared value**, stored once in the workspace;
3. the **effective value**, computed by the precedence rule and never stored as a fourth truth.

### 15.2 The precedence rule

For each field: **if the shared value is populated, it wins; otherwise the per-book value is used.**
"Populated" means a non-blank value after stripping surrounding whitespace — a field containing only
spaces is blank, because a user cannot tell it apart from empty.

Consequences the tests must pin:

- A populated shared field wins **even when the per-book field is also populated**, and the per-book
  raw value is **preserved, not destroyed** — clearing the shared field restores the per-book value
  exactly.
- A blank shared field leaves the per-book value effective.
- Both blank yields blank; the consumer decides what blank means for its own writes.

### 15.3 The disabled-control projection

One pure function returns the set of field names whose per-book control must be disabled — exactly
the fields whose shared value is populated. The UI layer *renders* that set; it does not compute it,
and it never decides precedence for itself.

This is what makes the requirement true in behaviour and not only in appearance: the user cannot edit
a value that will be ignored, because the control is disabled by the same fact that makes it ignored.

### 15.4 The field vocabulary belongs to the consumer

`shared/metadata.py` has no metadata dataclass and no public field-name constants, and the shared
importer deliberately contains no universal media list — each tool supplies its own
`SupportedTypeCatalog`. Plan 6 follows that precedent exactly: **the consumer declares its own field
set**, and the workspace validates values against it. A hard-coded universal metadata list here would
be wrong for M4B Maker, MP3 Tool and the Metadata Editor simultaneously.

## 16. Frozen effective values (Phase 5)

At run capture, on the main thread, before any worker starts:

1. resolve the effective value of every field for every book (section 15);
2. build **one `job_control.RunSnapshot` per non-empty, valid book**, through the existing
   `capture_run(...)`, passing that book's own `ImportedFileSnapshot` as `files` and its frozen
   configuration **plus its resolved effective values** as `tool_options`;
3. compose those into one immutable workspace-level record: an ordered tuple of
   `(book_id, RunSnapshot)` pairs, plus the frozen shared metadata as captured.

**Why one snapshot per book.** `RunSnapshot.item_ids` is the occurrence ids of its files, and
`FailureLog`, `RunResult` and `RetryRequest` are each scoped to a single `snapshot_id`. Giving each
book its own snapshot makes the book the natural retry unit, and lets Plan 6's retry be *literally*
`RunResult.retry()` returning a Plan 3 `RetryRequest` — no parallel snapshot framework, no
book-identity hidden inside an opaque dictionary. This was put to the maintainer at plan creation and
chosen deliberately over a single workspace-wide snapshot.

**Empty and invalid books get no snapshot.** They are recorded in the composition as skipped, with
their `book_id`, so the run can report them truthfully without attempting them (13A).

**The freeze is total.** After capture, a later GUI edit — a metadata field, a shared field, an
added file, a removed book — cannot reach the active run, because the run never consults the
workspace again. Tests must prove exactly that: mutate the workspace after capture and assert every
captured value is unchanged, and assert the composition holds the **same snapshot objects** by
identity, not equal copies.

**One `JobController` per run, not per book.** Pause, Resume and Cancel are batch-level; Plan 6 adds
no second controller and no second event stream.

## 17. Numbering (Phase 6)

### 17.1 The promotion

`mp3_tools/m4b_numbering.py` already implements Decisions 21A, 28A and 48A: a configurable start, a
`propose()` that advances nothing, a `commit()` that advances exactly once and refuses a token it did
not issue, and a docstring stating it has *no knowledge of what a book is*. Writing a second
allocator would be the duplication this drop is told to avoid, and importing upward from `shared/`
into `mp3_tools/` would invert the layering.

**Phase 6 moves the module to `scripts/Universal/shared/numbering.py` and leaves
`scripts/Universal/mp3_tools/m4b_numbering.py` as a thin re-export.** The maintainer approved this
cross-plan touch at plan creation.

**The regression gate is mandatory and blocking.** The move is behaviour-preserving or it is
reverted:

- `files/tests/test_m4b_numbering.py` passes **unchanged** — not edited, not re-pointed, not
  re-parameterised. Its 51 tests are the proof.
- `mp3_tools/m4b_converter.py` is **byte-identical**; it keeps importing `m4b_numbering` and keeps
  constructing `m4b_numbering.SuccessNumbers`.
- The logic in the moved file is byte-identical to the original apart from its module docstring.
- If any of that cannot be shown, **stop and report** rather than adjusting a Plan 5 test to fit.

### 17.2 The book-level contract

Plan 6 states, and tests, how a consumer must use the allocator for books:

- One `SuccessNumbers` per **run attempt**, constructed from the frozen start value — never from a
  live widget.
- `propose()` before the work, because the number may need to be written into the output; `commit()`
  **only** after that book has genuinely succeeded.
- **Nothing else consumes a number**: not a skipped book, not an empty book, not an invalid book, not
  one cancelled before it started, not a failed one. A test must run a three-book sequence in which
  the second fails and assert the third receives **2**.
- The counter is **not** part of the frozen snapshot. A snapshot is what a retry re-reads; a success
  counter is a fact about one attempt's execution. Keeping it out is what lets the snapshot stay
  retry-stable — the same reasoning the Converter recorded.

**Plan 6 owns the contract and the allocator. Plan 7 owns writing a series part into an M4B.** No
metadata is written here.

## 18. Retry and dispositions (Phase 7)

### 18.1 Book dispositions

Plan 3's `ItemStatus` has no `SKIPPED`, by design. Plan 6 defines the **book-level** disposition it
delegated: succeeded, failed, skipped-empty, skipped-invalid, and not-attempted (the run ended,
usually cancelled, before this book was reached).

**Only `failed` is retryable, and only when its underlying `FailureRecord` is retryable.** Not
attempted is emphatically not a failure and is never offered for retry — the same rule Plan 3 states
for items.

### 18.2 The result composition

A workspace-level result composes one `job_control.RunResult` per attempted book, keyed by `book_id`,
settled through the existing `RunResult.settle(...)`. It derives, without a second vocabulary: per-book
disposition, the ordered retryable book ids, the counts, and whether Retry Failed should be offered
at all (delegated to `job_control.is_available(JobAction.RETRY_FAILED, state, has_retryable=...)`).

**A book failure is not a run failure.** A run that lost some books but orchestrated correctly is
`COMPLETED_WITH_FAILURES`, matching Plan 3's rule exactly, and Decision 28A's continue-on-failure
follows from it.

### 18.3 Retry

`retry_failed_books()` returns an ordered tuple of **Plan 3 `RetryRequest` values, one per retryable
book**, each built by that book's own `RunResult.retry()` against **that book's exact original
`RunSnapshot` object**.

Tests must prove:

- object identity — each request's `snapshot` **is** the original snapshot, not an equal copy;
- book identity survives — the same `book_id` maps to the same snapshot across the retry;
- a retry reads **nothing live**: mutate every workspace field, the shared metadata and the file
  lists after the run, and the requests are unchanged;
- a skipped, empty, invalid or not-attempted book is never in the result;
- retrying consumes no number for anything that did not succeed, and a retried success takes the next
  number in sequence.

**Plan 6 does not execute a retry.** `RetryRequest` is a value; re-running it is the consumer's job,
exactly as it is today for the Converter, Cover and TTS panels.

## 19. UI contracts (Phase 8)

`shared/book_workspace_ui.py` follows `job_ui.py`'s idiom without exception: each class **owns** a
`frame`, every decision arrives as a callback, there is no universal base panel, teardown is
idempotent and survives a destroyed root, and **every public Tk-reaching method opens with
`MainThreadGuard.require`** so a worker is refused before a widget is touched.

Two components:

- **The book navigator** — Previous, Next, a `Book X of Y` label, Add Book, Duplicate Book, Remove
  Book. It renders availability from the model (Previous disabled at the first book, Next at the
  last) and **never** decides workspace semantics for itself. Remove Book asks its `on_remove`
  callback whether to confirm, passing the meaningful-work answer from section 13.3; the callback
  shows `job_ui.ask_confirm` or does not.
- **The Shared Metadata surface** — a distinct region built from the **already-approved** tokens:
  `ACT.Shared.TLabelframe` for the container, `ACT.SharedHeader.TLabel` for the header,
  `ACT.Shared.TLabel` / `ACT.SharedSecondary.TLabel` for body text, `ACT.Shared.TCheckbutton` for
  toggles, and `style_tk_widget(widget, theme, role="shared")` for any classic Tk widget. It renders
  the disabled-field set from section 15.3 through `job_ui.LockGroup` and computes no precedence.

**No new colour, metric or font token.** A panel must never re-declare a hex literal or a magic
number; everything comes from the theme bundle. If a genuinely new token were needed, that is a
maintainer decision, not a phase decision — stop and ask.

**The reusable list, controls and status bars are not re-created.** A consumer composes this
navigator alongside the existing `ImportAdapter` and `JobAdapter`; Plan 6 adds no second imported-file
list and no second job-control bar.

### 19.1 Layout acceptance

The navigator and the Shared Metadata surface are **bounded** content, so master index section 9
applies: they must fit without a whole-panel scrollbar in the maximized reference view, and adapt
gracefully at `920x600` with no inaccessible action and no clipped confirmation. The book collection
itself is variable-length and may scroll locally. `MIN_SIZE` does not change.

## 20. Platform contracts (Decision 29A)

- **One business layer.** `book_workspace.py` and `numbering.py` contain no `sys.platform`, no
  `os.name`, no Tk import and no platform branch of any kind. A structural test asserts it.
- **Windows** gets the approved dark design through the existing `ACT.Shared.*` styles.
- **macOS** keeps its native Finder appearance because the adapter asks for **no style at all** off
  Windows — `job_ui.style_name` returns `""` when the bundle has no `styles` key. The adapter never
  tests the platform itself; that is how the existing shared widgets stay native, and Plan 6 copies
  it exactly.
- **Never read a Windows-only metric unconditionally.** Aqua bundles have no `styles`, no `fonts`,
  and a smaller `metrics` set; `theme["metrics"]["gap_md"]` raises `KeyError` there. A test must
  exercise the adapter against an aqua-shaped and a classic-shaped bundle.
- Functionality is identical on both platforms. Appearance is the only difference.

## 21. Threading and state contracts

- **The data layer is thread-free.** It constructs no thread, lock, event, condition or queue, and
  reads no clock. A structural test asserts that, the way `test_plan3_boundaries` already asserts it
  for `importing.py`.
- **The workspace is main-thread-owned by contract, not by lock** — matching `ImportedFileManager`,
  whose source says the absence of a mutex is deliberate so the rule stays visible. The adapter's
  `MainThreadGuard` is where the rule is enforced against Tk.
- **Workers never touch the workspace.** They read a frozen `RunSnapshot` and communicate back by
  putting immutable values on the existing queue, drained by the single `MainThreadPump` `after`
  chain. Plan 6 opens no second scheduled callback.
- **Every update is atomic.** A rejected or failed operation leaves the workspace exactly as it was —
  the same all-or-nothing rule `ImportedFileManager.commit` already keeps.
- Cancellation is Plan 3's. Plan 6 adds no cancellation primitive and touches neither
  `shared/cancellation.py` nor `ImportCancellation`.

## 22. The output-filename boundary (Decision 51A)

Decision 51A eventually requires an optional per-book M4B output filename with safe automatic
fallback and collision numbering. The line is drawn as follows and stated in the drop so it cannot
blur:

**Plan 6 owns** — nothing more than this: if the source audit at Phase 1 confirms that an optional
per-book output-name field genuinely belongs to the generic book model, it may exist as **one
configuration key carrying the user's raw string, validated only as display-safe text**. It is
covered by section 13.2's configuration/inputs split and by section 15's precedence like any other
field.

**Plan 7 owns** — everything that makes it a filename: sanitisation, the automatic fallback when the
field is blank, collision numbering, destination planning, and writing the file. Those are
`output_paths` services under Plan 2's ownership, consumed by Plan 7.

**Plan 6 must not** call `sanitize_component`, construct a `DestinationPlanner`, reserve a run
directory, plan a destination, or produce any `Path` that is an output. A structural test asserts
that `book_workspace.py` imports `output_paths` not at all.

## 23. Test strategy and red-proof discipline

### 23.1 Red proof

- **A test counts as red proof for a newly claimed defect only if it demonstrably fails against the
  named pre-fix commit.** State the commit and the observed failure. Do not claim existing behaviour
  is broken without proving it.
- **Plan 6's functionality is new**, so its contract tests are red for the ordinary reason that the
  code does not exist yet. Say that plainly; do not dress it up as a discovered defect.
- **Never manufacture a destructive failing state** in the maintainer's workspace to produce a red
  test.
- Every guard that could be satisfied by an accident must be **mutation-checked**: break the
  behaviour deliberately, confirm the test goes red, restore. A guard that cannot fail is not a guard.

### 23.2 Test modules

New modules under `files/tests/`, following the house idioms: pure functions tested directly with no
fixtures; real trees under `tmp_path`; injected clocks and callbacks; `import tk_gate` with a
module-scoped `tk_root` fixture for the adapter; threads replaced by inline stubs; **no test sleeps**;
bounded joins.

| Module | Covers |
|---|---|
| `test_book_workspace.py` | The book job, identity, configuration freezing, workspace invariants, Add / Duplicate / Remove / navigation, atomicity, meaningful work |
| `test_book_grouping.py` | Decision 12A directory grouping, natural order on both import paths, no silent combining, empty groups |
| `test_shared_metadata.py` | The raw/raw/effective triple, precedence, the disabled-field projection, blank handling, per-book value preservation |

### 23.3 Structural-guard rule

Boundary guards use **AST inspection**, never substring matching. A substring guard is how a
boundary silently rots; the repository already has `files/tests/source_probe.py` for AST assertions
and it is the mechanism to use.

`git diff --check`; and the exact canonical documentation filename check. Skipped tests are named and
justified. A user-approved deferral is recorded as a deferral, **never** as a pass.

### 35.5 Operation contracts

- **Add** — appends a pristine book, selects it, leaves every existing book the *same
  object* in the same order, advances the revision once.
- **Duplicate** — copies the current book's configuration by value, starts at
  `NO_FILES`, mints a new identity, inserts **immediately after its source** and
  selects it. It **reads `FIELD_ROLES` rather than restating Decision 49A**: the
  identity field is minted, the configuration field carried, the inputs field reset, so
  a field added to `BookJob` later cannot be silently forgotten because `field_role`
  refuses to classify anything the table does not name.
- **Remove** — with several books the removed slot is taken over by whatever falls into
  it (the next book, or the new last one when the removed book was last). With one
  book it is replaced by a **fresh pristine book**: never a zero-book state, not even
  internally, and meaningful work is genuinely discarded.
- **Previous / Next** — one step, **non-wrapping**; at an end the action is simply
  unavailable and the revision does not move. No book is reordered and no book's own
  state is touched, so navigating away and back returns exactly what was left behind —
  structural here, because the state lives in the model rather than in widgets.
- **Select** — by stable `book_id`, never by index. An unknown identity is refused
  outright rather than clamped, because silently selecting *something* is how a user
  edits the wrong book. Selecting the current book is a no-op.
- **Replace** — the replacement **identifies its own target** through the `book_id` it
  carries, so an ordinary edit can never become a silent remove-and-add that loses the
  book's place in the order. A foreign identity is rejected. Replacing with an equal
  value is a no-op. There is deliberately no `replace_configuration` or `replace_files`
  beside it: one primitive that swaps a whole immutable value cannot disagree with
  itself about what a partial update means.

**`Book X of Y`** — `Y >= 1` and `1 <= X <= Y` after every one of the seven operations,
proved by iterating all of them. `X` and `Y` remain derived from the ordered tuple and
the selected id; neither is stored.

**Revision** — advances exactly once per real change and never on a no-op. Enforced
structurally, not by discipline: `test_exactly_one_place_advances_the_workspace_revision`
proves `_changed` is the **only** function that calls `advance()`.

**Atomicity** — every rejected operation returns the original value untouched: same
books, same selection, same revision. Every operation validates its workspace argument
**before** asking the factory for an identity, so a rejected call consumes no id;
a test asserts the next id is still `…-000001` after three rejections. Once a valid
workspace is in hand the remaining construction cannot fail. Making this transactional
in the harder sense would need a rollback inside Plan 3's `IdFactory`, which is not
this phase's to change — recorded, not hidden.

- **`NO_SHARED_METADATA`** — declares nothing; the workspace default.
- **`BLANK`** — what an unset field resolves to.
- **`is_populated`** — the one predicate.
- **`effective_value`**, **`effective_metadata`**, **`disabled_fields`** — pure
  projections.
- **`set_shared_metadata`** and **`SharedMetadataError`**.

**The vocabulary belongs to the consumer**, per section 15.4. No universal list
exists, and a guard checks that twice over: no constant named like one, **and** no
tuple/list/set literal anywhere in the module enumerating two or more audiobook tag
names — so renaming the constant is not enough to smuggle one in.

**Validation.** Field names go through the module's existing `_require_identifier`
(non-blank, no whitespace, no path separator). Duplicate declared fields are
refused. A value for an undeclared field is **refused, not dropped** — so narrowing
the vocabulary while a raw value still exists fails loudly rather than silently
orphaning what the user typed. Values must be `str`.

### 37.4 Populated, and one predicate

`is_populated` is non-blank after stripping, exactly as section 15.2 states: `""`,
`"   "` and `"\t\n"` are blank; `"Title"` and `"  Title  "` are populated.

**Stripping happens for the question only — raw stays raw.** A shared value of
`"  Padded  "` is populated *and* resolves to `"  Padded  "`, spaces intact; nothing
rewrites the stored value merely to test it.

**Precedence and the disabled projection ask the same function**, and that is
asserted structurally, not only behaviourally: no second blankness helper may be
defined, `populated` and `populated_fields` must both call `is_populated`, and
`disabled_fields` must reach it by delegating to `populated_fields` rather than
deciding for itself. A behavioural test additionally sweeps five raw values and
requires that "overrides", "is disabled" and `is_populated` agree on every one.

**On non-string values — a recorded finding.** Section 15.2 defines populatedness
for text, so `SharedMetadata` **refuses a non-string shared value** rather than
inventing semantics nobody has specified. This is a deliberate narrowing, not a
gap: the metadata fields a consumer would share (`title`, `artist`, `album`,
`album_artist`, `series`, `genre`, `year`, `comment`) all read back as strings from
`shared/metadata.py`, and the one integer, `track`, belongs to Decisions 21A/48A
numbering rather than Shared Metadata. If a consumer ever needs a non-text shared
field, that is a new decision, and this refusal is where it will surface loudly.

### 37.5 Decision 20B, proved end to end

The section 15.2 lifecycle is one test, step by step: per-book `"Per Book"`, shared
blank → effective `"Per Book"`, nothing disabled; set shared `"Series Shared"` →
effective is the shared value and `title` is projected disabled; **the book's raw
configuration still says `"Per Book"`**, both in the object and through the
workspace; clear the shared field → effective is `"Per Book"` again and nothing is
disabled. Clearing with whitespace is covered too.

That restoration is a property of **never having overwritten** the per-book value,
not of putting it back — and a separate test asserts the configuration mapping is
byte-for-byte what it was after an override.

**Multi-book and multi-field** behave independently: one shared value applies to
every book; clearing restores each book's own value with no cross-leakage; and with
shared `author` populated and shared `title` blank, each book gets the shared author
and its own title — the drop's worked example, asserted as whole mappings.

**`disabled_fields`** returns exactly the declared fields whose shared value is
populated: blank and absent fields are excluded, an undeclared field cannot enter
(construction already refused it), and the result is a deterministic `frozenset`.

### 37.6 Stored once, on the workspace

`WorkspaceSnapshot` gains one field, `shared: SharedMetadata = NO_SHARED_METADATA`,
validated in `__post_init__`. **`BookJob` gained nothing** — its fields are still
exactly `book_id`, `configuration`, `files`, and a guard asserts no `shared`,
`title`, `author` or `metadata` field appeared beside them. Per-book raw values stay
in `configuration`; there is no parallel per-book metadata mapping.

**No effective value is stored anywhere.** A guard asserts no field whose name
contains `effective` exists on `BookJob`, `WorkspaceSnapshot` or `BookMutation` —
because a stored copy is precisely how two truths come to disagree, and Phase 5
freezes these values into a run exactly *because* they are not frozen here.

### 37.7 Preservation through every operation

`_changed` — the one constructor every operation routes through — now carries the
workspace's shared value forward unless an operation explicitly replaces it. That
makes preservation a property of the single constructor rather than something each
of the nine operations must remember, and it is why **an import cannot silently
discard what the user shared across books**. A parametrized test drives all eight
prior operations (add, duplicate, remove, previous, next, select, replace, import)
and asserts the shared value survives each; a further test confirms an import
preserves it and that every newly created book resolves against it.

Decision 49A is untouched: Duplicate still copies the book's own configuration and
resets its inputs, and a test asserts the shared value is **not** copied into the
duplicated book — shared state stays at workspace level.

### 37.8 The update operation

`set_shared_metadata(workspace, shared)` changes only the shared value: the same
book objects come through, the selection does not move, `removed` is empty, and the
revision advances **exactly once**. Setting an equal value — including a distinct
but equal `SharedMetadata` — is a no-op that returns the same object and moves no
revision. A rejected update is atomic and consumes no identity.

**`WorkspaceOperation.SHARED_METADATA` is its own member.** It changes neither the
books nor the selection, so reporting it as `REPLACE` (one book) or `IMPORT` (every
book) would misdescribe what actually moved — the same one-member-one-scope rule
that kept `IMPORT` separate in Phase 3 and `WorkspaceOperation` separate from Plan
3's `ManagerOperation` in Phase 2.

### 37.10 Findings and deviations

1. **Non-string shared values are refused** (section 37.4). A deliberate narrowing
   that follows the drop's own definition of populatedness rather than inventing
   semantics; recorded so a future consumer needing one knows it is a new decision.
2. **`WorkspaceOperation.SHARED_METADATA` was added**, for the reason in section
   37.8 — the drop permitted exactly one such member if genuinely necessary.
3. **`shared/metadata.py` was inspected and deliberately not touched**; the Phase 0
   conclusion held.
4. **One of my own new guards was wrong and was corrected rather than loosened.**
   It demanded that `disabled_fields` call `is_populated` *directly*; in fact it
   delegates to the value's own `populated_fields` property, which calls the
   predicate. That indirection is the better shape, so the guard now asserts the
   real chain — `populated` and `populated_fields` call the predicate,
   `disabled_fields` delegates to `populated_fields` and does **not** re-decide —
   which is a stronger statement than the original.
5. **One constant went dead and was removed**: `PHASE4_NAMES` existed only for the
   Phase 4 absence guard it served, which Phase 4 replaced.
6. **Three tests required updating**, all expected transitions rather than defects:
   the operation-enum tests now name nine members, and the Phase 4 absence test
   became a **Phase 5** absence test. The absence boundary moves forward with the
   plan; it was not retired.
