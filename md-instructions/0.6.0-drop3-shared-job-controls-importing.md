## 3. Goal

Create a reusable foundation that:

1. owns an ordered imported-file collection with Add Files, Add Folder, selection, reorder, remove, clear, counts, supported-type selection, deduplication, and deliberate duplicate override;
2. scans one or more folder roots off the Tk thread with safe natural direct-files-first depth-first traversal, live count, independent Cancel Import, hidden/link/unreadable handling, warnings, and atomic commit;
3. retains source-root and relative-path information compatible with Plan 2 output planning;
4. freezes inputs, effective configuration, and tool options before a run and exposes a consistent input-lock contract;
5. provides truthful cooperative pause, resume, cancel, stage, progress, and processing-state primitives without freezing threads or subprocesses;
6. defines Summary/Details events, current-run rolling ETA, failure records, and Retry Failed requests that always reference frozen original configuration;
7. provides narrow reusable Tk adapters whose worker communication is queue-based and main-thread-only; and
8. leaves every existing production tool's current behavior unchanged until its assigned adoption plan.

### 5.3 Behavior preservation and UI isolation

- No production panel or launcher imports or instantiates the new foundation in this drop; add structural regression tests to enforce that boundary.
- Do not alter current file filtering, ordering, cancellation, output, metadata, audio, or layout behavior in any production tool.
- New reusable Windows widgets may use `ACT.*` namespaced styles only. Do not configure generic ttk styles or visually convert a classic panel.
- Preserve macOS aqua/Finder appearance in reusable adapters.
- Keep `MIN_SIZE = (920, 600)` and `DEFAULT_GEOMETRY = (1024, 720)` unchanged.

### 5.4 Truthful cooperative control

- Pause and cancel are cooperative requests, not claims that a running OS call stopped instantly.
- A worker inside an indivisible stage stays in `PAUSE_REQUESTED` and pauses only at the next safe checkpoint.
- Cancel overrides pause, wakes a paused worker, and reaches `CANCELLED` only after worker acknowledgement/cleanup.
- Do not hold a lock while calling user code, blocking on a queue, waiting on a condition, or performing filesystem/subprocess work.
- Do not permit a second run/controller to mutate the first run's snapshot or state.

### 5.5 Filesystem and data safety

- Scan only roots explicitly supplied in the immutable request.
- Use lexical absolute paths and `lstat`/`scandir`-style checks that detect links before traversal; do not call `resolve()` in a way that follows an entry before it is authorized.
- A cancelled, declined, failed, or closed import never changes the current imported-file manager.
- Scanning never writes to source trees, output roots, settings, runtime data, or timestamps intentionally.
- Automated tests use disposable roots only. Never scan the real repository root, user home, Downloads, network share, or media library.
- Do not silently overwrite inputs or outputs and do not reserve an output run in Plan 3's importer/job-control specimen.

## 6. Detailed design contract

### 6.1 Imported-file model

Use immutable value objects with stable occurrence identity:

- `SupportedType(id, label, extensions)`: normalized dot-prefixed case-insensitive extensions; stable type ID; no MIME probing in this drop.
- `ImportRoot(root_id, path, order)`: one direct file group or selected folder root, in user-selected order.
- `ImportedFile(occurrence_id, path, source_root, relative_path, supported_type_id, identity)`.
- `ImportProblem(root/path, category, display_message, technical_detail)` with categories including unsupported, duplicate, hidden, link, unreadable, vanished, wrong-type, cancelled, and invalid-root.
- `ScanRequest` and `ScanResult` as frozen snapshots/tuples.

`relative_path` is relative to the selected folder root and includes the filename. Individually added files have no mirroring root and later route through flat planning. Paths used internally remain absolute; UI presentation may shorten them.

### 6.2 Supported types and direct Add Files

- Every adopting tool will supply its own immutable supported-type catalog later; the shared layer contains no hard-coded universal media list.
- All supplied types are selected by default. Any combination, including none, is representable; attempting an import with none selected produces a validation message and starts no worker.
- Add Files validates each selected path as an existing regular, non-link file with a selected supported extension.
- Directly selected hidden files are accepted because the user chose them explicitly; hidden-directory policy applies to folder traversal.
- Dialog filter order is not a trust boundary. Every returned path is revalidated.
- Preserve user/dialog order for direct Add Files. Natural traversal order applies to Add Folder.

### 6.3 Natural folder traversal

For each root, in the order roots were supplied:

1. Validate the root as an existing readable non-link directory.
2. Enumerate one directory with `os.scandir`.
3. Refuse/report links, junctions, reparse points, unsupported entries, vanished entries, and unreadable entries without following them.
4. Sort compatible direct files by a stable natural key and emit them first.
5. Sort eligible child directories by the same natural key, then recurse depth-first.
6. Check import cancellation before enumeration, during entry classification, before each recursive descent, and before result publication.

Natural comparison is Unicode-aware, case-insensitive for ordering, and splits digit runs numerically so `1, 2, 10` is produced. Ties use a deterministic original-name/path fallback. Root order is never globally resorted.

An individual `scandir` or filesystem metadata call may temporarily block on a slow/network filesystem. Status text must not promise instantaneous cancellation; the next checkpoint is the bound.

### 6.4 Hidden and link policy

- `include_hidden_folders` defaults to `False` and is frozen in the scan request.
- A directory is hidden when it has a dot-prefixed name (except `.`/`..`), a Windows hidden attribute, or a supported platform hidden flag. Tests inject platform detection; they do not depend on the current host alone.
- Hidden directories are skipped and reported when the option is off. When on, they are traversed under the same link/readability rules.
- Folder traversal skips hidden files and reports them; a user may still add a hidden file explicitly with Add Files.
- Never follow a symlink, junction, mount-like reparse point, or alias represented as a filesystem link, whether encountered as a root, file, or directory.
- A platform facility that cannot be safely classified fails closed and becomes a reported problem.

### 6.5 Deduplication and intentional override

Default duplicate identity must avoid both false additions and false collapsing:

- Prefer a non-following file identity from `lstat`/platform file metadata when available, so the same physical file added through different spellings or hard links is recognized.
- Fall back to a Unicode-normalized lexical absolute path key; casefold on Windows and preserve case on POSIX. Do not use `resolve()` to follow links.
- Compare candidates against both the existing manager snapshot and earlier candidates in the same transaction.
- The default skips duplicates and records each one.
- The explicit `Allow duplicate files` option is off by default, visible in the reusable adapter, and frozen per import request. When enabled, a duplicate receives a new occurrence ID but retains the same source identity. It is never disguised as a different source file.

This contract respects case-sensitive macOS volumes while still deduplicating the same physical file when file identity is available.

### 6.6 Imported-file manager operations

The manager owns an ordered tuple/list of `ImportedFile` occurrences and an immutable revision number. It exposes:

- snapshot/count/selected-count;
- atomic append of a completed import transaction;
- remove selected;
- clear;
- move selected block up;
- move selected block down; and
- stable selection restoration by occurrence ID.

For multi-selection reorder, selected occurrences preserve their relative order, move as one logical block across adjacent unselected items, never wrap, and leave selection on the moved occurrences. Removing or clearing the manager never deletes source files.

The manager is mutated only on the main thread. Worker scanners return candidates; they do not hold or mutate the manager.

### 6.7 Import coordination, warnings, and atomic commit

- Broad-root warning occurs before scanning. At minimum, broad roots are a filesystem/volume root, a UNC share root, or the exact user home directory. The check is injected/testable and never scans merely to decide.
- Declining the broad-root warning starts no worker and changes nothing.
- The import worker reports typed state, discovered-compatible count, problems, completion, cancellation, and fatal error through a queue.
- `Cancel Import` controls only the active import scan. It never calls the processing job's cancel controller.
- The live count is the number of compatible non-link candidates discovered so far before final manager deduplication. Final Summary distinguishes discovered, proposed additions, duplicate skips, other skips, and problems.
- After a completed scan, calculate the proposed addition count using the frozen duplicate policy. If it is greater than the captured `EffectiveConfig.importing.large_result_warning_threshold`, show confirmation. Equal to the threshold does not warn.
- There is no hard maximum.
- Only an accepted, complete `ScanResult` is committed. Confirmation decline, cancel, error, adapter close, or manager revision conflict commits nothing.
- If the manager changed while the scan ran, do not merge against stale state silently. Recompute the transaction against the new revision on the main thread or require a new confirmation when the proposed count/duplicates materially changes.

### 6.8 Plan 2 configuration and output integration

- Capture one `EffectiveConfig` before starting an import and carry it in the immutable request; never re-read the threshold mid-scan.
- `ImportedFile` retains enough source-root and relative-path information for later use by `plan_flat`, `plan_mirrored`, and `plan_multi_root`.
- Add contract tests that convert manager snapshots into the input groupings expected by Plan 2 planners without changing `output_paths.py`.
- No import action reserves or creates an output run.

### 6.9 Job state model

Use an explicit thread-safe state machine. At minimum:

- `IDLE`
- `RUNNING`
- `PAUSE_REQUESTED`
- `PAUSED`
- `CANCEL_REQUESTED`
- `CANCELLED`
- `SUCCEEDED`
- `COMPLETED_WITH_FAILURES`
- `FAILED`

Document every legal transition and reject illegal transitions deterministically. A controller belongs to one run; terminal state cannot be reused as a new run by silently clearing events.

### 6.10 Cooperative pause, resume, and cancel

- `request_pause()` moves a running job to `PAUSE_REQUESTED`.
- At a safe pausable checkpoint, the worker acknowledges `PAUSED` and waits on a condition without busy-spinning.
- `resume()` wakes the worker and returns it to `RUNNING`.
- At an indivisible stage, the controller remains `PAUSE_REQUESTED`; UI text says `Pause requested` and the current operation continues until the next safe checkpoint.
- `request_cancel()` is legal from running, pause-requested, and paused states; it wakes paused waits, marks cancellation requested, and causes the next checkpoint to raise the existing cancellation exception.
- The worker/runner marks `CANCELLED` only after it has stopped starting new work and performed its owned cleanup.
- A terminal success/failure/cancel event is emitted exactly once.
- No Python thread suspension and no OS process suspension are permitted.

### 6.11 Frozen run snapshots and input locking

`RunSnapshot` is immutable and contains:

- ordered imported occurrences and their stable IDs;
- a deep-frozen/copy-safe tool-option mapping or typed tool-option object supplied by a later adopter;
- the captured `EffectiveConfig`;
- supported-type/import options relevant to the run;
- a run/snapshot ID and creation time from an injected clock; and
- any later adopter's destination-mode choice only as part of its frozen tool options. Plan 3 defines no output-policy type and reserves no path.

The Tk adapter captures widgets/variables on the main thread before creating the worker. Workers receive only the snapshot.

Registered input and processing-option controls are disabled for running, pause-requested, paused, and cancel-requested states. Pause/Resume/Cancel, log tabs, progress/status, and Open Output remain enabled when their state makes them meaningful. Production panels do not adopt this contract until their later plans.

### 6.12 Job events, Summary, Details, and technical logging

Use typed immutable events with injected timestamps and stable run/item identifiers. Event kinds cover:

- state and stage changes;
- progress/current item;
- import count;
- user-facing warning;
- failure;
- output location;
- completion/cancellation; and
- technical detail.

Summary shows milestones, current stage/item, progress, warnings, failures, output location, ETA, and final result. It must not be flooded with every raw command or per-file diagnostic.

Details shows timestamped per-file/per-stage activity, diagnostics, useful subprocess output, and exception detail. Technical events also go through the existing session logger. Do not create a second log file/retention system.

Event rendering is a UI concern; event production is Tk-free. User-facing messages remain concise and technical tracebacks/commands remain in Details/logs.

### 6.13 Current-run rolling ETA

- Use an injected monotonic clock.
- Build ETA only from completed comparable work units in the current run and the current work-kind/stage category.
- Default reliability policy: at least three comparable completed samples and a rolling window of at most the latest twenty.
- Exclude paused time, cancelled units, and failed/incomplete units from duration samples.
- When total work is unknown, samples are insufficient, categories change, timing is invalid, or the estimate is otherwise unreliable, return `Calculating…` rather than a number.
- Clamp no misleading negative duration/ETA and handle zero-duration fake-clock tests deterministically.
- Format display centrally; keep estimator math UI-free.

Media duration probes are not processing-history samples and must not be substituted for measured work time.

### 6.14 Failure collection and Retry Failed

`FailureRecord` is immutable and includes occurrence/item ID, stage, concise user message, technical detail, retryable flag, and original snapshot ID.

- Item-level failures may be collected without forcing a job-level `FAILED` state; later tools decide continuation policy.
- `COMPLETED_WITH_FAILURES` exposes Retry Failed only when at least one retryable failure exists.
- `RetryRequest` references the exact original `RunSnapshot` and an ordered subset of failed IDs. It never reads current widgets, settings, or manager contents.
- Internal engine/network retries and Fast-to-Safe fallbacks remain distinct from user-facing Retry Failed.
- Plan 3 does not decide tool-specific retry output placement or rerun stages. Later adoption plans must use Plan 2 output services and document that choice.

### 6.15 Reusable Tk adapters and developer harness

`shared/job_ui.py` may provide narrowly reusable components/adapters for:

- an extended-selection imported-file list with count and Add Files/Add Folder/Move Up/Move Down/Remove/Clear actions;
- supported-type and include-hidden/allow-duplicates import options;
- live import status and separate Cancel Import;
- Pause/Resume/Cancel control state;
- `ProgressIndicator` plus ETA/status;
- Summary/Details tabs or view switch; and
- main-thread queue polling and close-safe teardown.

Use composition and callback/protocol boundaries rather than a universal base panel or inheritance hierarchy that later tools must fight.

A developer-only harness under `files/tests/` may instantiate these adapters for manual validation. It must not be imported by the launcher, shipped in release archives, write real outputs, scan broad real locations, or become a seventh production tool.

### 6.16 Subprocess and lifecycle boundaries

- Existing synchronous `subprocess_utils.run` stages are indivisible for this foundation. Pause/cancel applies at the next checkpoint.
- This plan does not terminate ffmpeg/network/model processes, switch existing tools to `popen`, or claim an in-flight process stopped.
- Do not change the Edge runner's process-wide `os.chdir` behavior; Plan 4 owns any required serialization/removal.
- Do not add launcher-wide shutdown coordination. The reusable pollers/harness must close safely, while production lifecycle adoption remains with the tool plans.
