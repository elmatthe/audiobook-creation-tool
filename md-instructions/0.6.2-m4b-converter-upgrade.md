## 9. The immutable conversion-plan layer

A converter-local, pure, Tk-free module holds the planning vocabulary. Names are indicative; the
architecture is the requirement.

```python
@dataclass(frozen=True)
class SegmentPlan:
    order: int                 # 1-based within the item
    start: float               # seconds, inclusive
    end: float                 # seconds, exclusive (== source duration for the last segment)
    title: str                 # source chapter title, may be blank
    destination: Path          # planned, collision-safe, final
    track: int | None          # split: structural order; whole-book: see §20

@dataclass(frozen=True)
class ItemPlan:
    occurrence_id: str
    source: Path
    source_root: ...           # import provenance, drives mirroring
    duration: float
    chaptered: bool            # False => chapterless fallback (18A)
    segments: tuple[SegmentPlan, ...]

@dataclass(frozen=True)
class ConversionPlan:
    snapshot_id: str
    mode: str                  # "whole" | "split"
    metadata_mode: str         # "preserve" | "strip" | "replace"
    replacement: Mapping[str, str]
    auto_number: bool
    start_number: int
    quality: int
    run_directory: Path
    items: tuple[ItemPlan, ...]
    unusable: tuple[ItemFailure, ...]
    @property
    def total_segments(self) -> int: ...
```

### Lifecycle — authoritative order

1. **Main thread** freezes the imported snapshot and every widget value; `capture_run` produces the
   `RunSnapshot` with `tool_options`.
2. **Worker thread (never Tk)** probes each source for chapters and duration. **No ffprobe call may
   run on the Tk main thread** — a 47-chapter, 24-hour book must not block the UI.
3. Items that cannot be probed are classified **unusable** with a typed reason — explicitly, never by
   falling through to "chapterless".
4. The **immutable `ConversionPlan`** is built: spans, titles, structural tracks, destinations.
5. The run directory is reserved and destinations planned here — after validation, before any write.
6. `total_segments` becomes the authoritative progress denominator, published once.
7. Execution begins.
8. **Retry Failed re-executes the frozen `ConversionPlan`** — no re-probe, no re-read of current UI
   state. The only values not frozen before success are whole-book success numbers (§20), which are
   allocated at success time by design. Any deliberate safety revalidation added later must be
   explicit, documented and tested — never implicit.

## 11. Chapter probing, validation, and the complete-timeline plan

### 11.1 Probe result — no ambiguity

A **typed immutable result**, in the converter-local module — not global `shared/ffmpeg_utils.py`,
which today has no chapter vocabulary and no other current consumer.
`metadata.read_chapter_titles` stays as the Metadata Editor's titles-only helper and is not reused.

```python
class ProbeStatus(Enum):
    OK = "ok"                        # probe succeeded (chapters may be empty)
    PROBE_FAILED = "probe_failed"    # ffprobe error / unparseable output
    NO_DURATION = "no_duration"      # no usable format duration
    NO_AUDIO = "no_audio"            # no audio stream

@dataclass(frozen=True)
class SourceChapter:
    index: int
    start: float
    title: str

@dataclass(frozen=True)
class ChapterProbe:
    status: ProbeStatus
    duration: float | None
    chapters: tuple[SourceChapter, ...]
    detail: str = ""
    @property
    def ok(self) -> bool: ...
```

A valid file with zero chapters is `OK` with an empty tuple. An ffprobe failure is `PROBE_FAILED`.
**Operational failure is never disguised as "chapterless."**

### 11.2 Validation — conservative, on **starts only**

The plan (§11.3) consults only chapter **starts** and the source **duration**, so every chapter-end
anomaly becomes structurally irrelevant and there is nothing to "repair".

**Fail the item** on structural invalidity — **typed, non-fatal, nothing written, and NOT eligible
for in-place `Retry Failed`**: `PROBE_FAILED` · `NO_DURATION` · `NO_AUDIO` · any start `< 0` · any
start `>= duration` · **non-monotonic starts** · **duplicate starts** (would yield a zero-length
segment). Do **not** sort, clamp or drop chapters to make a malformed map fit. A materially
contradictory chapter structure must not be silently rewritten into a different semantic book.

> **Retry eligibility — maintainer correction (Phase 13, approved Option A).** This clause previously
> read "typed, retryable, nothing written", which was ambiguous: it could be read as making these
> items candidates for the shared in-place `Retry Failed` control. They cannot be. A
> preflight-unusable occurrence never obtains an executable `ItemPlan`, so it has **no frozen
> `SegmentPlan`, no frozen destination, and no retained collision planner** once Start-time planning
> is complete. Retrying it in place would therefore require re-probing, rebuilding the
> `ConversionPlan`, planning a destination after Start, or retaining mutable planning state — every
> one of which §21 forbids.
>
> So these failures stay **typed** and fully visible in Summary and Details with their reason, stay
> **non-fatal** (the rest of the batch converts normally), write nothing, and are recorded
> `retryable=False`. **A corrected source is submitted through a NEW RUN**, which probes and plans it
> normally — that is the only route by which a formerly unusable source can acquire the executable
> plan entry and frozen destination an in-place retry requires.

**Chapterless fallback** (18A) applies to exactly one case: `status == OK` and `chapters == ()`.
It is **not** a blanket corruption-recovery mechanism.

**Tolerance** may be used only for numerical comparison and probe precision — deciding whether two
starts are equal (structural invalidity), and emitting warnings. **A tolerance is never permission to
trim or discard source audio.**

### 11.3 Complete-timeline plan — chapter-start partition (46A)

For N usable chapters with starts `s₁ … s_N` and source duration `D`:

```
segment i = [ bounds[i], bounds[i+1] )
bounds    = [ 0.0, s₂, s₃, …, s_N, D ]
```

Segment *i* is labelled with source chapter *i*'s title. Output count is exactly N.

- Pre-roll before chapter 1 belongs **inside chapter 1's output**. **No synthetic `"Opening"` file is
  created.**
- Interior unchaptered time belongs to the preceding segment, by virtue of the partition.
- Trailing audio belongs to the final segment, whose end is the real source duration.

**Invariants, asserted structurally in tests:**

- `segments[0].start == 0.0`
- `segments[-1].end == D`
- `segments[i].end == segments[i+1].start` for all i
- `Σ (end − start) == D` within numerical tolerance
- every segment has `end − start > 0`
- `len(segments) == len(chapters)`

**Validated during planning against five real fixtures** (15 / 47 / 50 / 39 / 44 chapters): every one
tiles `[0, D]` with `Σ − D = 0.000000000`. For well-formed sources the partition equals the native
chapter spans exactly; one fixture's last segment absorbs a **0.046 s** tail and another absorbs float
imprecision — **both without any discard rule**. A synthetic pre-roll case (first start 41.062 s)
places the pre-roll inside chapter 1's output and remains lossless.

### 11.4 ffmpeg seek shape — evidence-driven, not pre-locked

This drop fixes the **required outcomes**, not the CLI ordering:

- no missing audio at any boundary;
- no duplicated audio at any boundary;
- accurate output duration for every segment;
- acceptable performance on a real multi-hour audiobook;
- the xHE-AAC decoder path preserved;
- cancellation still effective mid-segment.

Phase 5 compares candidate command shapes on deterministic generated fixtures **and** a
representative real M4B, measuring boundary accuracy and runtime, then **pins** the chosen form.
Prefer expressing the span as an explicit **duration** (`end − start`) over an absolute end unless
measurement shows otherwise. Reaching a contradiction is a stop gate.

## 14. Naming contract (45A)

**Whole book / chapterless:** `<source stem>.mp3`, collision-numbered by `DestinationPlanner`
(today's behaviour, unchanged).

**Split segment** — a two-stage seam. Stage 1 exists because `output_paths.sanitize_component`
treats separators as **path hierarchy** and reduces the string to its last element. A metadata title
is **one component**, so its separators must first become visible punctuation:

```python
_SEPARATORS = {"/": " - ", "\\": " - ", "\x00": ""}

def flatten_title(title: str) -> str:
    """Path separators inside a metadata title are punctuation, not hierarchy."""
    text = title or ""
    for bad, good in _SEPARATORS.items():
        text = text.replace(bad, good)
    return " ".join(text.split())          # collapse whitespace

def segment_filename(order: int, total: int, title: str) -> str:
    width = max(2, len(str(total)))
    body = flatten_title(title)
    body = (sanitize_component(body, fallback=f"Chapter {order}")
            if body.strip() else f"Chapter {order}")
    return sanitize_component(f"{order:0{width}d} - {body}.mp3")
```

Stage 2 delegates **all** reserved-name, forbidden-character, Unicode/NFC, trailing-dot/space and
component-length rules to the existing repository sanitiser. **Nothing is hand-rolled.**

**Proven output** (executed during planning against a real fixture and edge cases):

| Input title | Result |
|---|---|
| `1 — There is no food here / Meg ate all the Swedish Fish / Please get off my hearse` | `01 - 1 — There is no food here - Meg ate all the Swedish Fish - Please get off my hearse.mp3` |
| `Chapter 1: To Goldicia` | `03 - Chapter 1_ To Goldicia.mp3` |
| `""` / `"   "` / `".."` | `04 - Chapter 4.mp3` (etc., per order) |
| `CON` | `06 - _CON.mp3` |
| `"A" × 300` | capped at 255 chars, **`.mp3` intact** |

**Mandatory regression test:** the full slash-containing real title must prove that the order prefix
survives, that **meaningful text from every portion** of the slash-separated original survives, that
no path hierarchy is created, that `.mp3` is preserved, and that the result is valid on Windows and
macOS. Order numbers restart at 1 for each item.

## 16. Structural tag rules

A **split** output is a fragment and must never describe the unsplit book.

- **Dropped in every split output:** the source **chapter map** (`-map_chapters -1`), the whole-book
  `title`, any track/disc **totals**, and all whole-book structural atoms.
- **Regenerated in split outputs:** `title` = segment title, `track` = structural segment order.
- **Not inherited in split outputs:** anything outside the §15 allowlist, including unknown freeform
  atoms — *not* copied merely because ffmpeg could copy it.

A **whole-book** output *is* the whole book, and its timeline is complete and unchanged.

- **Preserve and Replace both retain the source chapter map** (`-map_chapters 0`). **(D6A, approved.)**
  An MP3 can carry chapters, the map still describes the output accurately, and dropping it would be
  a silent navigation regression.
- **Strip removes it** along with everything else.

## 17. Artwork (D2 approved)

- **Preserve** — keep existing embedded artwork when compatible and safely identifiable.
- **Strip** — remove artwork.
- **Replace** — keep the source artwork while replacing the approved textual/generated fields.
- **Plan 5 adds no replacement-image picker**, and no UI or documentation may imply the user can
  supply replacement artwork. That is Plan 8.

Implementation requirements:

- Copy **only** a stream positively identified as embedded attached artwork — inspect stream
  **disposition**; never map arbitrary source video merely because a video stream exists.
- A source with **no artwork is valid** and must not fail.
- Preserve by **stream copy** where technically valid; do not re-encode unnecessarily.
- Every split segment of a book receives the same book cover.
- Test the real **PNG** and **JPEG/MJPEG** attached-picture cases present in the fixture set.
- **Independently verify** with a reader/probe that artwork is present or absent in the resulting MP3
  according to the selected mode — never assume the flag worked.
- If real ffmpeg/container behaviour shows this contract cannot be met safely, **stop at the risk
  gate with evidence** rather than silently changing the policy.

## 18. Execution, process lifecycle, and cancellation

Reserve once per run (`reserve_run_directory("m4b_converter")`), then execute segments.

### 18.1 Output safety

Every segment is written to a **temporary name in the destination directory** and moved into place
only after the return code **and** the drift guard pass. No incomplete file ever carries a
successful-looking name.

**The >3 % duration-drift guard is preserved and made per-segment**: compare each output's measured
duration against its own planned span (`end − start`), not the whole source. On breach, discard the
output and fail the item with the existing xHE-AAC-aware message.

### 18.2 Subprocess contract — must not deadlock

`shared.subprocess_utils.popen` is a thin pass-through, so polling a process whose `stdout=PIPE` is
never drained **will block** once ffmpeg fills the OS pipe buffer. The contract:

1. Spawn via `sp.popen` with **stdout/stderr redirected to a temporary file** rather than a pipe —
   no buffer to fill, no draining thread, no deadlock. (A dedicated reader thread into a bounded
   buffer is an acceptable alternative; an undrained `PIPE` is not.)
2. Poll `proc.poll()` on a short interval, checking the controller between polls.
3. On cancel: `terminate()` → **bounded grace period** → `kill()` → **always `wait()`/reap**, so no
   zombie remains on either platform.
4. Delete the partial temporary file.
5. Retain a **bounded diagnostic tail** (~2000 chars) into the failure `detail` for Details; Summary
   structurally cannot read `detail`.
6. Distinguish **cancellation requested** from **cancellation settled** — settled only after the
   child is reaped and temporary files removed.
7. **All child-process creation goes through `shared.subprocess_utils`**, preserving the
   hidden-console behaviour on Windows.
8. Validated on **Windows and macOS** by tests that terminate a real child process.

### 18.3 Pause / Resume / Cancel (38A)

- A segment's ffmpeg call is **indivisible**. The UI shows **Pause requested**, and the run pauses at
  the **next segment boundary**, where the worker calls `controller.checkpoint()`.
  **Never claim a running ffmpeg is paused.**
- Cancel **does** act mid-segment, via §18.2.
- `LockGroup` locks imported inputs and processing options while running (**9A**).

### 18.4 Progress and ETA

- **The progress unit is the segment**, with `ConversionPlan.total_segments` as the denominator, so a
  47-chapter book does not sit at a single tick. Whole-book mode yields one segment per item, i.e.
  today's file-count behaviour.
- ETA via the existing `EtaEstimator` (3-sample minimum, 20-sample window, `Calculating…` when
  unreliable). Progress is never rounded up to 100 % while work remains.

## 19. Output organisation and collision safety (D3 approved)

Bridge the imported queue to the planners with `importing.planning_groups(snapshot)`:

| Case | Planner | Decision |
|---|---|---|
| Individually chosen files | `plan_flat` | **31A** |
| One folder root | `plan_mirrored` | **7A** |
| Several folder roots | `plan_multi_root` | **41A** |

**Decision 31A is followed literally.** Directly selected M4Bs write **flat into the unique run
folder**, in both modes:

```
M4B-Converter-N/01 - Chapter Name.mp3
```

Split mode does **not** create a per-book subfolder for directly selected files. Where several
directly selected books produce identical chapter filenames, **collision-safe destination planning
handles it** (`01 - Intro.mp3`, `01 - Intro-1.mp3`). Do not introduce a source-stem container for
convenience, and do not silently supersede 31A.

**Folder-imported M4Bs** keep the approved mirroring semantics: one root mirrors directly, several
roots use collision-safe named root containers. **Split segments are placed at the mirrored location
corresponding to that item's provenance.**

One shared `DestinationPlanner` from `reservation.planner()` serves the whole run, so flat and
mirrored outputs can never collide. `assert_not_input(destination, sources)` on every planned path.
No existing file is ever overwritten. The Converter has no source-side or custom-destination exception.

**Use the public primitives directly** — `planning_groups`, `plan_flat`, `plan_mirrored`,
`plan_multi_root`, `DestinationPlanner`. A small Converter-specific adapter mapping occurrence ids to
planned destinations is acceptable. **Do not copy TTS's or Cover's private
`plan_destinations` / `_identity_buckets` / `_pair` implementations wholesale.** If this third adopter
proves a non-trivial bridge genuinely belongs in shared infrastructure, **stop at the shared-contract
risk gate** and return the duplicated behaviour, existing consumers, proposed seam and regression
surface before extracting anything.

## 20. Three distinct numbering concepts (D5 approved)

These are **not** one counter and must be implemented separately.

**1. Split filename order prefix (45A)** — the item's structural segment order, `1…N`, frozen in the
`ConversionPlan`. Independent of success and of every other item. Retry-stable.

**2. Split structural `track` metadata (19A/47A)** — also the item's structural segment order.
Frozen. Retry-stable. **A failure in another book never renumbers a successful split book's internal
chapter order.**

**3. Whole-book optional sequential success numbering (`Auto-number tracks` + `Start #`)** — the only
counter that interacts with success.

- **Frozen configuration (37A):** the run snapshot freezes auto-number enabled/disabled, `Start #`
  and every other run option. Retry Failed uses those original frozen settings.
- **Success-only allocation (21A):** do **not** pre-assign a final sequential number to every item
  before execution. Maintain a success counter. When an item is about to produce a whole-book
  success: the next number is *tentative*; the output must fully pass conversion, finalisation and
  validation; **only then is the number consumed**; a failure consumes nothing.
- **No gaps (28A).** Worked example, verified: Book A succeeds → 1 · Book B fails → consumes nothing ·
  Book C succeeds → 2 · later Retry Failed of Book B succeeds → 3. Gap-free, duplicate-free, and the
  retry still ran on the original frozen configuration.
- The output number is derived from **successful execution order**, so 37A does not require it to be
  frozen before success occurs. **This is not an exception to 37A.**
- Auto-numbering does not apply in split mode, where `track` is structural.

## 21. Failure and cleanup semantics

- **Per-item boundary (28A):** one item's failure never affects another item's outputs.
- **Per-segment:** a failed segment fails its **item**; already-written segments of that item are
  removed, so a partially split book never masquerades as complete.
- Items classified unusable during preflight (§11.2) fail before anything is written.
- Cancelled items are `NOT_ATTEMPTED`, not failures, and are not retryable.
- **Retry Failed** re-executes the frozen `ConversionPlan` for failed items only, reusing the
  destinations planned at the original Start.
  - It applies **only** to failed items that possess an **executable `ItemPlan`** in the original
    `ConversionPlan`, and it re-runs that item's frozen `SegmentPlan`s at their **exact original
    destinations**. A split item is retried **whole** — every one of its frozen segments, in frozen
    order — never a single failed chapter.
  - **Preflight-unusable entries (§11.2) are not candidates.** They hold no executable plan entry
    and no frozen destination; they are recorded `retryable=False` and are corrected by starting a
    new run.
  - **Cancelled items remain `NOT_ATTEMPTED`** and are not retryable.
  - **Invariant:** every id a settled `RunResult` reports as retryable has a corresponding
    executable `ItemPlan` in the frozen plan. A retryable id without one is an internal contract
    violation: the retry is refused truthfully with a bounded diagnostic, never repaired by
    re-probing or re-planning.
  - **Cleanup.** Phase 11 already removes the temporary candidate and any earlier finalised segments
    of a failed item *before that item settles*, so a normal settled failure leaves no partial book
    behind and two generations cannot coexist. Retry therefore **verifies** its frozen destinations
    are free before writing — and if one is unexpectedly occupied it **fails safely**. There is no
    persistent ownership token proving an occupant is a stale tool-owned partial, so an unknown file
    is never deleted merely to clear the slot, and Phase 11's no-overwrite contract is not weakened.

## 23. Thread safety

- Every Tk value is read on the main thread before the worker starts; the worker sees frozen values.
  `job_ui.MainThreadGuard` / `MainThreadPump` enforce this.
- **Probing is worker-side** (§9 step 2). No ffprobe call blocks the Tk thread.
- One worker thread ⇒ one event producer ⇒ use `JobReporter.for_run(...)` directly; no
  `RunPublisher` wrapper is needed (Cover's simpler shape, not TTS's).
- Workers emit immutable `JobEvent`s onto a queue; the pump drains on the main thread. No widget is
  touched from the worker, including for progress and logging.

## 24. Platform rules

- Windows-illegal characters, reserved device names, trailing dots/spaces, NFC and the 255-char cap
  are handled by `sanitize_component` — never hand-rolled. Title separators are handled by
  `flatten_title` **before** it (§14).
- Do not regress Plan 4 hardening: `sanitize_relative` rejects drive/UNC/device syntax on every
  platform; case-insensitive collisions are `DestinationPlanner`'s responsibility.
- All subprocess calls go through `shared/subprocess_utils`; no console flashes on Windows.
- Long paths: a deep mirrored tree plus a 255-char name can exceed Windows limits — test a deep-tree
  case and fail truthfully rather than silently.
